# NeoWPF build setup

## Requirements

NeoWPF requires C++20.

NeoWPF currently supports:

Windows: x64 + D3D11
Linux: x64 + Vulkan

CMake is required. Git and vcpkg are required for dependency installation.

NeoWPF builds its normal library as a static library.

The following CMake options are available:

```
NEOWPF_RENDERER_BACKEND
NEOWPF_STATIC_DEPENDENCIES
NEOWPF_USE_NEOLINT
NEOWPF_BUILD_MEDIA
NEOWPF_BUILD_DOTNET
NEOWPF_IGNORE_BAD_XAML
```

Defaults in a normal checkout:

```
NEOWPF_RENDERER_BACKEND    Windows: D3D11
                            Linux: Vulkan

NEOWPF_STATIC_DEPENDENCIES ON
NEOWPF_USE_NEOLINT         ON
NEOWPF_BUILD_MEDIA         OFF
NEOWPF_BUILD_DOTNET        OFF
NEOWPF_IGNORE_BAD_XAML     OFF
```

`NEOWPF_BUILD_DOTNET` is normally kept OFF. Local development may enable it with `-DNEOWPF_BUILD_DOTNET=ON`.

## Windows

### Install Git

Using winget:

```powershell
winget install --id Git.Git -e
```

or Chocolatey:

```powershell
choco install git -y
```

### Install Visual Studio

Install Visual Studio with the **Desktop development with C++** workload.

Make sure the MSVC x64/x86 build tools, Windows SDK, and C++ CMake tools are installed. Visual Studio provides CMake integration for C++ projects.

### Install CMake

```powershell
winget install --id Kitware.CMake -e
```

Check the installation:

```powershell
cmake --version
```

CMake 3.20 or newer is required by NeoWPF.

When using the `Visual Studio 18 2026` generator from the command line, CMake 4.2 or newer is required because that generator was added in CMake 4.2.

### Install vcpkg

Clone vcpkg:

```powershell
cd C:\
git clone https://github.com/microsoft/vcpkg.git
cd vcpkg
.\bootstrap-vcpkg.bat
```

Add vcpkg to PATH:

```powershell
$env:Path += ";C:\vcpkg"
[Environment]::SetEnvironmentVariable(
    "Path",
    [Environment]::GetEnvironmentVariable("Path", "User") + ";C:\vcpkg",
    "User"
)
```

Open a new terminal after changing the permanent PATH.

Verify:

```powershell
vcpkg version
```

### Clone NeoWPF

```powershell
cd C:\
git clone https://github.com/Asterin-Digital/NeoWPF.git
cd NeoWPF
```

### Install dependencies

NeoWPF uses the `x64-windows-static-md` vcpkg triplet on Windows.

```powershell
vcpkg install --triplet x64-windows-static-md #
```

The triplet must match the architecture used to build NeoWPF. vcpkg supports selecting a triplet with `--triplet`, and CMake can also select the target triplet with `VCPKG_TARGET_TRIPLET`.

### Windows SDK path

When `NEOWPF_STATIC_DEPENDENCIES=ON`, NeoWPF merges the Windows SDK static archives into its final archive.

Set `NEOWPF_WINDOWS_SDK_ROOT` to the directory containing the x64 Windows SDK `.lib` files.

Example:

```powershell
$env:NEOWPF_WINDOWS_SDK_ROOT = "C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\um\x64"
```

The SDK version can be different on your machine.

To find installed Windows SDK versions:

```powershell
Get-ChildItem "C:\Program Files (x86)\Windows Kits\10\Lib"
```

Make sure the selected directory contains libraries such as:

```
d3d11.lib
dxgi.lib
ole32.lib
dbghelp.lib
windowscodecs.lib
```

NeoWPF will fail during configuration when static dependency merging is enabled and `NEOWPF_WINDOWS_SDK_ROOT` is not set.

### NeoLint

NeoLint checks are enabled by default.

NeoWPF expects the versioned NeoLint Release executable at:

```
NeoLint/
└── NLintBuild/
    └── Windows/
        └── Release/
            └── NeoLint.Windows.Release.<version>.exe
```

The expected version is read from:

```
NeoLint/NeoLintVersion.txt
```

NeoLint also requires:

```
.neolint.json
compile_commands.json
```

`compile_commands.json` is generated by Ninja or Makefile generators, not Visual Studio generators.

Because NeoLint is enabled by default, the easiest command-line build on Windows is therefore to use Ninja.

Install Ninja:

```powershell
winget install --id Ninja-build.Ninja -e
```

Then open a **Developer PowerShell for Visual Studio** so the MSVC compiler environment is available.

Build with Ninja:

```powershell
cmake -S . -B build -G Ninja `
    -DCMAKE_BUILD_TYPE=Release `
    -DNEOWPF_RENDERER_BACKEND=D3D11

cmake --build build
```

For Debug:

```powershell
cmake -S . -B build `
    -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug `
    -DNEOWPF_RENDERER_BACKEND=D3D11

cmake --build build
```

If NeoLint has not been built yet, disable it temporarily:

```powershell
cmake -S . -B build `
    -G Ninja `
    -DCMAKE_BUILD_TYPE=Release `
    -DNEOWPF_RENDERER_BACKEND=D3D11 `
    -DNEOWPF_USE_NEOLINT=OFF
```

A custom NeoLint executable can also be supplied:

```powershell
-DNEOWPF_NEOLINT_EXECUTABLE="C:\path\to\NeoLint.exe"
```

### Visual Studio builds

Visual Studio generators are multi-configuration generators, so `Debug` or `Release` is selected when building rather than during configuration.

With CMake 4.2+:

```powershell
cmake -S . -B build-vs `
    -G "Visual Studio 18 2026" `
    -A x64 `
    -DNEOWPF_USE_NEOLINT=OFF `
    -DNEOWPF_RENDERER_BACKEND=D3D11
```

Build Release:

```powershell
cmake --build build-vs --config Release
```

Build Debug:

```powershell
cmake --build build-vs --config Debug
```

NeoLint should be disabled for this build tree unless `compile_commands.json` is provided another way.

Do not reuse the same build directory after switching between Ninja and Visual Studio. CMake build trees are tied to their generator.

## Linux

### Install system dependencies

On Ubuntu:

```bash
sudo apt install -y \
    git \
    build-essential \
    cmake \
    ninja-build \
    pkg-config \
    libvulkan-dev \
    glslang-tools \
    wayland-protocols \
    libwayland-dev \
    libxkbcommon-dev \
    libfreetype6-dev \
    libharfbuzz-dev \
    libfontconfig1-dev \
    zlib1g-dev \
    libpng-dev
```

These packages provide the compiler, CMake, Ninja, Vulkan development files, Wayland development files, `wayland-scanner`, FreeType, HarfBuzz, Fontconfig, zlib, and PNG support used by the Linux build.

A working Vulkan driver is also required to actually run NeoWPF applications.

### Clone NeoWPF

```bash
git clone https://github.com/Asterin-Digital/NeoWPF.git
cd NeoWPF
```

### Install vcpkg

```bash
git clone https://github.com/microsoft/vcpkg.git ~/vcpkg
cd ~/vcpkg
./bootstrap-vcpkg.sh
```

Add it to PATH:

```bash
echo 'export PATH="$PATH:$HOME/vcpkg"' >> ~/.bashrc
source ~/.bashrc
```

Verify:

```bash
vcpkg version
```

### Install dependencies

NeoWPF uses the `x64-linux` triplet:

```bash
cd ~/NeoWPF
sudo vcpkg install --triplet x64-linux
```

The dependencies are installed into the NeoWPF vcpkg installation used by the project.

### Configure

```bash
cmake -S . -B build -G Ninja \
    -DCMAKE_BUILD_TYPE=Release \
    -DNEOWPF_RENDERER_BACKEND=Vulkan \
    -DCMAKE_TOOLCHAIN_FILE="$HOME/vcpkg/scripts/buildsystems/vcpkg.cmake" \
    -DVCPKG_TARGET_TRIPLET=x64-linux
```

Build:

```bash
cmake --build build
```

Debug:

```bash
cmake -S . -B build-debug -G Ninja \
    -DCMAKE_BUILD_TYPE=Debug \
    -DNEOWPF_RENDERER_BACKEND=Vulkan \
    -DCMAKE_TOOLCHAIN_FILE="$HOME/vcpkg/scripts/buildsystems/vcpkg.cmake" \
    -DVCPKG_TARGET_TRIPLET=x64-linux

cmake --build build-debug
```

## NeoLint checks

NeoLint is enabled by default:

```
NEOWPF_USE_NEOLINT=ON
```

NeoLint reads the generated:

```
compile_commands.json
```

and validates the NeoWPF source tree before NeoWPF is compiled.

To disable it:

``1
-DNEOWPF_USE_NEOLINT=OFF
```

For a normal Ninja build:

```bash
cmake -S . -B build -G Ninja \
    -DCMAKE_BUILD_TYPE=Release \
    -DNEOWPF_USE_NEOLINT=ON

cmake --build build
```

NeoLint requires a Release executable matching `NeoLintVersion.txt`.

NeoLint itself uses LLVM/Clang, so its first dependency build may take substantially longer than a normal NeoWPF dependency installation.

## .NET interop

`NeoWPF.DotNet` is optional and is OFF by default.

Enable it with:

```
-DNEOWPF_BUILD_DOTNET=ON
```

A working `dotnet` executable is required when this option is enabled.

Check:

```powershell
dotnet --version
```

or:

```bash
dotnet --version
```

The generator project is located at:

```text
dotnet/NeoWPF/Interop/Generator/Generator.csproj
```

NeoWPF builds the generator before `NeoWPF.DotNet`.

For local development:

```
-DNEOWPF_BUILD_DOTNET=ON
```

For a normal committed/default build:

```
-DNEOWPF_BUILD_DOTNET=OFF
```

## NeoWPF.Media

`NeoWPF.Media` is optional and OFF by default.

Enable it with:

```
-DNEOWPF_BUILD_MEDIA=ON
```

This fetches LuAudio from:

```
https://github.com/Past-Horizon/LuAudio.git
```

The repository and Git tag/branch can be overridden with:

```
-DNEOWPF_LUAUDIO_GIT_REPOSITORY=<repository>
-DNEOWPF_LUAUDIO_GIT_TAG=<tag-or-commit>
```

## XAML compiler

NeoWPF normally expects the XAML compiler to already exist as a prebuilt tool.

It first checks:

```
tools/XamlCompiler.exe
```

on Windows or the platform equivalent.

If it is not present, it looks in:

```
NWpfBuild/<Platform>/<Configuration>/tools/
```

A missing XAML compiler can therefore cause XAML-related build failures even when the C++ dependencies are installed correctly.

## Tests

Tests can be enabled with:

```text
-DBUILD_TESTING=ON
```

For Ninja:

```bash
ctest --test-dir build --output-on-failure
```

For a Visual Studio build:

```powershell
ctest --test-dir build-vs -C Release --output-on-failure
```

The test suite uses GoogleTest, which CMake fetches when testing is enabled.

## Install

NeoWPF can be installed after a successful build.

Ninja:

```bash
cmake --install build
```

Visual Studio:

```powershell
cmake --install build-vs --config Release
```

The installed layout contains the NeoWPF libraries and public headers.

## Build defaults

Windows:

```
Architecture: x64
Renderer: D3D11
vcpkg triplet: x64-windows-static-md
Static dependency merging: ON
NeoLint: ON
NeoWPF.Media: OFF
NeoWPF.DotNet: OFF
```

Linux:

```
Architecture: x64
Renderer: Vulkan
vcpkg triplet: x64-linux
Static dependency merging: ON
NeoLint: ON
NeoWPF.Media: OFF
NeoWPF.DotNet: OFF
```

If vcpkg cannot be found or the required triplet dependencies are missing, CMake will stop during configuration.

When changing generators, delete the old build directory and configure a new one.
