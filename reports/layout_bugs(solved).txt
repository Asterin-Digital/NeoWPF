# Grid / Layout Issues

## 1. Border desired size is much larger than WPF

### WPF

```
Text:    92x32
Padding: 10

Border Desired:
92 + 20 = 112
32 + 20 = 52
```

### NeoWPF

```
Text:    94x41
Padding: 10
Border: 1

Border Desired:
136x83
```

The extra 20 pixels almost perfectly matches another application of padding.

### Cause

Border owns padding.

ContentPresenter also owns padding.

Both are inflating DesiredSize.

---

## 2. ContentPresenter should not own Border padding

### Status

Very likely incorrect.

Current implementation:

```
Border
    ↓
ContentPresenter
    ↓
Text
```

Both Border and ContentPresenter subtract padding.

Both add padding back.

Result:

```
Text

+ Presenter padding

+ Border padding

= Double padding
```

---

## 3. Border passes its padding into ContentPresenter

```
presenter->SetPadding(GetPadding());
```

This is likely not how WPF behaves.

The ContentPresenter inside a Border is basically transparent.

It shouldn't know anything about Border padding.

---

## 4. ContentPresenter measures with reduced available size

Current:

```
available
- padding
```

WPF:

```
Border:
    subtracts padding

ContentPresenter:
    measures normally
```

Padding should only be removed once.

---

## 5. ContentPresenter adds padding into DesiredSize

Current:

```
Desired = Child + Padding
```

Should probably be

```
Desired = Child
```

Border already adds padding.

---

## 6. ContentPresenter arranges with reduced size

Current

```
Arrange(
    finalWidth - padding,
    finalHeight - padding
)
```

Should probably simply be

```
Arrange(finalWidth, finalHeight)
```

because Border already computed the inner rectangle.

```

Grid::Arrange
```

multiple times.

* ColumnDefinitions change

# Architecture

---

## 20. ContentPresenter responsibilities

Current

```
ContentPresenter

- padding
- measuring
- arranging
- desired size inflation
```

In WPF it's much lighter.

It mostly exists to

* host content
* participate in templates
* present the child

Border should own layout spacing.
